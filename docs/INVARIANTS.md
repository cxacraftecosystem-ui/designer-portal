# Invariants and traps

Since 0.0.10 the source carries no comments or docstrings (`scripts/tools/strip_comments.py --check`
fails Checks on a new one). The reasons that used to sit above the code live in `docs/` instead. This
page holds the ones that are invariants or traps: break one and something fails a long way from the
edit. Each entry names the code it governs and where its full original text can still be read
(`git show v0.0.9:<file>`).

| # | Invariant | Code |
|---:|---|---|
| 1 | The queue worker is its own process, and its unit is called `fieldrepo-queue` | `backend/app/worker.py` |
| 2 | Only one queue drain runs per host | `backend/app/services/media_queue.py` |
| 3 | The database code knows PostgreSQL and nothing else about it | `backend/app/core/db.py`, `backend/app/core/config.py` |
| 4 | Settings come from the process environment, then `backend/.env` by absolute path | `backend/app/core/config.py` |
| 5 | The Prisma client is generated by one script, never by `prisma generate` alone | `backend/scripts/generate_prisma_client.py` |
| 6 | Migrations must keep the previous release working | `backend/deploy/blue_green.sh` |
| 7 | The API has no hard memory ceiling; the queue does | `backend/deploy/blue_green.sh`, `infra/terraform/user_data.sh` |
| 8 | Gathered reads are bounded by the pool, not by the request | `backend/app/services/concurrency.py` |
| 9 | A read's size cap comes from `MemAvailable` and the cgroup, never `MemFree` | `backend/app/services/memory_budget.py` |

## 1. The queue worker is its own process

The web service is one uvicorn process. With more than one worker, uvicorn's supervisor health-pings
each worker and kills any that does not answer in time. A heavy transcription chunk once starved that
answer, the supervisor killed the worker mid-job, and the killed process orphaned its Prisma
query-engine subprocess. One orphan per kill exhausted the database's connection ceiling, after which
every database call returned 500 while `/health`, which touches no database, kept returning 200.

So the queue (`python -m app.worker`) is a plain `asyncio.run` loop under systemd with
`Restart=always` and `KillMode=control-group`, and the web units run with
`MEDIA_QUEUE_WORKER_ENABLED=false`.

**The unit name is the product's pre-rebrand name and is correct.** `fieldrepo-queue.service` and
`fieldrepo-api@<port>.service` are installed on the live box, and `deploy-backend.yml` restarts them by
those literal strings. Renaming one in the repository alone turns every deploy into a restart of a unit
that does not exist; under `set -e` that fails after the new code is unpacked, while the old process
keeps draining the queue with the old code. A rename is a coordinated migration over SSM in one change.

## 2. One queue drain per host

Both entry points (the worker, and the in-process drain a developer can switch on) take an OS advisory
file lock (`acquire_queue_worker_lock`). A second drain refuses to start rather than running silently
beside the first. Where `fcntl` does not exist (local Windows), the lock is granted, because there is
nothing to arbitrate.

## 3. The database code knows only PostgreSQL

`db.py` once matched a provider's pooler hostname and rewrote the port, and every pool setting rode on
that match. When the deployment moved, the match stopped firing and took the settings with it, silently.
Now every decision turns on shape (is the host local?) or on an explicit setting:

- `DATABASE_USE_TRANSACTION_POOLER` declares, per DSN, that the endpoint is a transaction pooler.
- `connection_limit` is a reduction against a pooler's shared budget. Against a direct endpoint it can
  be an increase over what the engine would choose, so it is written only where a pooler is declared or
  an operator chose the number.
- Migrations need a session (advisory locks, DDL). `prisma migrate deploy` reads `DATABASE_URL` raw and
  never sees `Settings`.

Requirement text says PostgreSQL. Where production runs is stated once, in
[ENVIRONMENT.md](ENVIRONMENT.md), and checked by `docs/tools/check-docs.mjs`.

## 4. Where settings come from

Highest first: the process environment (systemd `EnvironmentFile`, a ConfigMap, a command prefix);
then `backend/.env`, resolved by absolute path so the working directory cannot change which database a
command talks to; then field defaults. `backend/.env.production` is read by no code; the deploy copies
it to the box, which is how its values arrive as environment.

## 5. The Prisma client is generated by one script

prisma-client-py writes `prisma/types.py` without `from __future__ import annotations`. Under Python
3.14's deferred annotations, every one of its tens of thousands of `TypedDict` classes evaluates its
annotations against a fresh copy of the module globals, which is quadratic: measured on 2026-10-09,
`from prisma import Prisma` went from 13 s on Python 3.12 to over 20 minutes on 3.14.

`scripts/generate_prisma_client.py` runs `prisma generate`, adds the future import, then moves the
TypedDicts to `types.pyi` (editors read it; no process holds it). On 2026-10-19 that took the API from
956 MB resident plus 623 MB in swap to a fraction of it. CI, the deploy, the Dockerfile and a laptop all
run the script; `--check` fails if the installed client lacks either change.

## 6. Migrations must keep the previous release working

The deploy is blue/green: the new release starts on the idle port (8000 or 8001), passes `/health`,
and nginx switches with a reload. Migrations run first, **while the old release is still serving**.
So a migration adds, and a later release drops: never rename or drop a column the previous release
reads. If `prisma migrate deploy` fails three times, the script stops the live API and tries five more
times; that path has downtime and says so in the log.

## 7. Memory ceilings are asymmetric on purpose

Unbounded, the kernel's OOM killer picked uvicorn because the queue was hungry, and the API then
answered 502 for a reason nowhere in its own logs. The API gets `MemoryHigh=1000M` and no
`MemoryMax`: killing the API to save memory is the outcome these limits exist to prevent. The queue
gets `MemoryHigh=800M` and `MemoryMax=1100M`, because a killed queue restarts and its job is retried.
The box was a t3.micro until 2026-09-17 (it thrashed with steal time 0, which ruled out CPU credits), a
t3.small until 2026-10-10, and a t3.medium since; see [CI.md](CI.md).

## 8. Gathered reads are bounded by the pool

Independent reads in one request are gathered, never run one after another, but through a semaphore
sized to `DATABASE_CONNECTION_LIMIT`. A bare `asyncio.gather` lets one request hold every connection,
and this codebase has exhausted a pooler twice. With 5 connections per process, a page with eight
reads runs in two waves; that is the semaphore working.

## 9. Size caps come from the box

Every in-process read that could be large asks `memory_budget` how much it may claim. It reads
`MemAvailable` (not `MemFree`, which excludes reclaimable cache and would refuse everything on a healthy
box) and, inside a container, the cgroup's `memory.max` minus `memory.current`, because a container sees
the host's `/proc/meminfo`. The smaller answer wins. Standard library only.

## 10. Transcription temp files

Every recording the queue transcribes is streamed to a temporary file and cut into parts. These once
went to the system temp directory; on the Documentation Portal a run of failed downloads left 798 MB
behind, the quota filled, and transcription stopped (D37). Now they go to `TRANSCRIPTION_WORK_DIR`
(default `var/work` under `backend/`), with a size budget (`TRANSCRIPTION_WORK_DIR_MAX_MB`, 2048) that sweeps
then refuses, and a sweep of files older than `TRANSCRIPTION_WORK_STALE_MINUTES` (180) at worker start
and before each new file. Only names the module hands out are ever swept, so pointing the variable at a
shared directory deletes nothing else.

## 11. Ranks are stored comparisons

`ROLE_RANK` values are compared everywhere. Renumbering one silently changes every comparison at once,
so new tiers go into gaps: `DESIGNER` at 35 in the gap the tens left, `INSPECTOR` at 37, the middle of
the free 36 to 39 band, so a later tier fits on either side. The token is `INSPECTOR` while the label
reads "Inspector / Reviewer" because "review" already names a relational permission
(`can_review_record`, "may act on anyone ranked strictly below me").

## 12. `MINISTRY_ADMIN` is not an admin

`is_admin` is set membership, `{ADMIN, MASTER_ADMIN}`, not a rank floor, so rank 48 passes no admin
gate. What the tier holds beyond its rank it holds through named sets (`ACCOUNT_PROVISIONER_ROLES` and
the post sets). And "not an admin" is not "reads nothing sensitive": all three directorate tiers clear
every `has_rank(user, "PROFESSOR")` floor, including an artisan's unmasked Aadhaar number. See
[PERMISSIONS.md](PERMISSIONS.md) §2.

## 13. Shared trees

The questionnaire engine, the transcription package and their Android trees are byte-identical in
both portals, each pinned by a manifest in `shared/`. Edit them here, then run the sync scripts
(`scripts/sync_questionnaire.py`, `scripts/sync_transcription.py`, `scripts/sync_transcript_web.py`,
`scripts/transcript_android.py`). `shared/questionnaire-features.json` is identical in both and lists
every cross-client feature with its test tag on each client.
